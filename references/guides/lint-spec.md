# Plan lint spec — mechanical checks

Every check is a literal copy-paste command: run from the **repo root**, in any POSIX shell, plain `sh`/`grep`/`sed`/`awk` only. Replace `<slug>` with the initiative directory name (workspace = `docs/plans/<slug>/`). The rows are the Markdown contract and remain copy-pasteable as the canonical direct checks.

For Full without equivalent harness automation, use the connected extraction/capture recipe in
[full-checks.md](full-checks.md#execute-canonical-lint-faithfully). It compares actual saved script
bytes before interpreting a row; a successful altered command cannot count as canonical PASS.

- Pass conditions are mechanical — an output count or an exit code, no judgment. Any output line is a finding to report verbatim.
- No command uses the pipe character, so every cell copy-pastes verbatim from raw or rendered markdown: shell `A || B` is spelled `if A; then :; else B; fi`, awk alternation is spelled as summed tests, and the table separator is `sprintf("%c",124)`.
- Row 1 skips content inside fenced code blocks — done-signals legitimately grep for literal `{{…}}` placeholder patterns there (D-04).
- Row 2 selects `tasks/` with T ids for new workspaces and retains the published P resolver for `points/` workspaces. New T workspaces reject mixed identities, missing briefs and unresolved dependencies; mixed task directories fail before either resolver. A pre-§5 legacy P plan may use its exact board IDs as declarations; new T workspaces require `plan.md` §5.
- Row 4 resolves citation paths from the repo root first, then retries with the `docs/plans/<slug>/` prefix. A citation pinned to a revision (`path@<rev>:NN — "fragment"`) records grounding at that revision and is not re-checked: pin only a citation whose target the Task itself changes, and verify it with `git show <rev>:path`.
- Row 8 reads activity only from the trimmed Status field. Write scope (legacy `Touches`) may be inline (plain or backtick-quoted, comma-separated) or a multiline bullet list headed by `**Touches**`; annotations after quoted paths are ignored. Empty or unsupported declarations, globs, parent traversal and any existing symlink component (including dangling links) report unresolved scope, never a clean comparison. Ordinary future paths are compared lexically without requiring existence.
- Row 9 reads `**Type**` on its field line and counts `Rounds`, `Metric` and `Threshold` only as declarations outside fenced code: a bold field (`**Rounds**: 3` or `**Rounds:** 3`, also inline after the Type) or a line that starts with `Rounds: 3` — backtick-quoted prose mentions neither trigger nor satisfy it.
- Row 11 guard-skips historical workspaces without a usage ledger (pre-5.2); new workspaces use `resource-usage.md`. On workspaces that carry the ledger, row 11 flags a completed task missing its usage row — a ledger defect (fix the ledger, not the row).
- Row 12 scans the selected `tasks/*.md` or legacy `points/*.md` briefs for `**Effort**:` lines with any bullet marker (`-`, `*`, `+`): a `tasks/` brief carries a resolved `low`/`medium`/`high`/`max`; legacy `points/` also keep their historical `inherit`; any other value is red.
- Rows 3, 8, 10, 11 and 14 read Status through one shared extractor: the column whose header cell is exactly `Status` in the row just above a delimiter row, or the fifth data column when no header names it. Row 10 reads `Verification` by name.
- Row 14 checks every 🟢 or Complete row, not the first; rows 11 and 14 emit every matching id through the shared Status extractor. Workspaces that are neither active nor selected fail row 14 as sweep WARN, non-gating; active or selected workspaces gate — a missing closure report blocks execution until written or explicitly waived, even for an all-complete selected board.
- Row 15's date→epoch conversion feature-detects GNU vs BSD `date` exactly as `probe()` does; both flavors cover macOS and Linux hosts.
- Row 6 covers `history-archive.md` or historical `log-archive.md`; the archive's newest entry must not be younger than the active history's oldest. The cross-file comparison is composed in the same direct shell loop (cells stay single-purpose).
- Judgment-only checks (contract churn, quality dimensions, Q-guard…) stay in `decompose-and-lint.md` Step 6.5 — this table holds only what a command can decide.

Lifecycle validity semantics include duplicate starts, duplicate terminals, orphan terminal without start, mismatched Task/Role, and negative counts as invalid; an interrupted run with one `observe-incomplete` terminal is valid. The exact eight-column legacy `Point` table remains readable before v2 adoption; it is not parsed as lifecycle events. New lifecycle headers say `Task`; historical `Point` headers remain readable. `n/a` counts remain unknown and valid, as specified by `usage-observability.md`; empty, negative and nonnumeric counts still fail. A legacy header after v2 cannot hide invalid events.
