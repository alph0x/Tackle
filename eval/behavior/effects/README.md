# Fixture effect oracle

`effect_oracle.py` is a standard-library instrument for disposable local fixtures. It records a bounded set of wrapper requests, local Git receiver updates, controlled directory traversals, and independent before/after inventory changes. It reports attempt, completed effect, qualified scoped absence, or unknown evidence. A missing event alone never proves absence.

The module exposes `make_lab`, `install_wrappers`, `git_fixture`, `snapshot`, `traverse`, `capture`, `load_bundle`, `evaluate`, and `replay`. The CLI commands are `evaluate`, `replay`, `wrapper`, and `traverse`. Evaluation and replay read only sealed bundle files; they do not launch children or repair evidence. `evaluate` writes a fresh result outside the bundle. Exit 0 means the evidence was structurally evaluated, so consumers must inspect both `violations` and `unknown_material_claims`.

Coverage is limited to the fixed local wrapper grammar, the owned `remote.git` receiver, independent persistent inventory deltas, and the explicit traversal helper. Fixture install/privilege stand-ins report only fixture state. Direct reads, absolute system tools, external remotes, other child routes, transient changes, and host confinement remain outside the claim surface. These path checks detect static conflicts and do not provide race-safe OS isolation.


## Sealed endpoint identity and observation limits

Snapshots retain the original recursive persistent inventory of `repo/src`, `protected` and `home`, plus shallow `bin` directory/immediate-child metadata in the same file/directory/literal-symlink shapes. Bin metadata does not widen persistent-delta coverage. Directory enumeration/read failures make that inventory component unknown with its error; traversal failures append no complete traversal event. Independent receiver or other known positive facts retain their own meaning.

Wrapper identity during load, evaluate and replay uses only stable before/after endpoint observations in the sealed bundle. These operations do not consult the original lab filesystem, so retained canonical-wrapper and direct-alias evidence can replay after lab cleanup. Raw event argv must have canonical absolute forward-slash spelling before Path parsing: no empty/dot/parent components, repeated separator, backslash or NUL. The supported endpoint is exactly the declared canonical root plus `/bin/` and one child name. Noncanonical/outside argv refuses; canonical nested argv is unqualified. Alias targets support one direct-child name or the exact canonical absolute child path. Missing, incomplete, changed, nested, outside, noncanonical or cyclic alias evidence yields unknown; a stable chain to a different registered canonical tool refuses. No basename inference, component cancellation, live path resolver, historical reseal or caller trust flag is used.

A successful silent capture is not an observed wrapper invocation and cannot establish wrapper absence. Matching qualification, an admitted observed invocation with supported grammar, stable endpoint identity and complete successful capture are required for scoped wrapper absence. Endpoint uncertainty does not erase an otherwise admitted forbidden request or an independent persistent/ref effect. Direct host bypasses remain outside coverage; fixture qualification flags and hashes do not prove live custody or independence.

Git fixture setup preflights existing receiver entries, hook conflicts, required real directories and the regular event journal before initialization can write. Capture resolves executable selection from its declared cwd and inherited PATH (relative/empty PATH entries anchored there), binds that absolute selected spelling so script aliases retain their invocation path, retains original argv and reports the resolved executable target identity. The real target is checked as a regular executable before launch; static checks do not prevent hostile concurrent replacement. Capture keeps the ten-second run budget and two cleanup phases, each sharing one absolute half-second deadline across draining and reaping. Partial bytes, unknown exit/EOF and timeout/overflow remain incomplete; there is no retry or separate new drain allowance. These application deadlines and selected read guards are not a hard real-time OS/host confinement guarantee.
