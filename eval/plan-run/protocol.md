# Preregistered evaluation protocol — PR-EVAL-1

This is a planned experiment, not a result. Freeze this text/hash before observing any arm. A change creates a new protocol id and separates cohorts. Method arm A is the exact 7.3.0 source snapshot/commit; B is the complete refactored candidate snapshot. Task, allowed inputs, initial tree, executor binding, effort and budget match within each pair. Record planner model and planning budget as well; preferred same planner profile for both arms. Randomize arm order by seed with recorded order; no feedback from one arm to another.

Primary cohort: nine families below × three paired independent seeds (54 executor episodes, 27 paired instances), desired Luna High with planner Astra. These are requested local mappings, not observed capabilities or automatic paid-call permission. One paired seed/family is an 18-episode smoke. Medium can be a separately reported identical cohort if access/budget permit; Extra High is not automatic repair. Optional stronger executor arm measures the remaining gap only. No-skill calibration is optional and never substitutes for A/B.

Budget per arm: one planning episode capped at 20 minutes and 60 tool calls, one Run episode capped at 30 minutes and 100 tool calls; at most 3 failed correction cycles per Point and 2 initially unattributed integration cycles under the target contract. For fair budget accounting baseline's native nested retry rules still stop at the same total wall/tool caps; record that externally imposed ceiling. At most one risk-triggered cold probe plus one recheck, included in planning totals. No external planner repair after handoff. Wall times are observed, not promised; request/token/currency caps remain n/a until the harness exposes a comparable limiter and the owner authorizes paid usage. Capability check must precede execution. Stop at the first cap; never infer permission from available limits.

## Isolation and scoring
Oracle maintained by fixture author/evaluator, separately hashed. Evaluated planner/executor receive only participant task, initial source and their method install. Do not give this protocol's hidden case matrix, historical answers, fixture GROUND-TRUTH or other arm outputs to them. A fresh prompt with access to the original repository is not isolation: use separate allowed read roots or sanitized environment. Audit transcript/file-access evidence for leakage before scoring; inability to establish isolation makes the run invalid/unavailable, not a null. Fixture author and comparison orchestrator must not be treated as cold evaluated agents. Evaluate product results against oracle from the task, independent of generated Points/tests.

Functional correctness uses all required oracle cases; fidelity checks files/paths/schema/stdio/exits/effects only as specified. Code rubric uses correctness, stated O(n)/no-mutation/no-dependency bounds and integration readability: record each observable violation and allow equivalent designs. Do not use aesthetic preferences or test count alone. Method-compliance and product-success are separate columns. Record observed arm/model/effort, source/task/oracle/protocol hashes, starts/stops, tool evidence, user commands and manual interventions. Run all synthetic validator positives and negatives before using its scores; no test expected value may be copied from candidate output.

## Outcomes and denominators
First Run episode begins at first authorized Run invocation against its sealed plan, includes internal retries/resumptions and ends at complete/blocked/budget exhaustion. First-episode success requires integrated oracle correctness without manual intervention or frontier replanning; report internal repair counts even on success. Clean success adds zero failed correction cycles. Denominator: every valid eligible started episode, including blocked, failed, skipped required scope and unverifiable outcomes. Invalid/contaminated runs are excluded from correctness denominators but listed with reason, spent cost and replacement run id. Planned-but-not-started runs are listed separately. Also report paired completed subset for like-for-like cost, with selection limitation; never silently drop hard failures from primary success rate.

Metrics: functional pass fraction, code rubric violations, exact/semantic artifact fidelity, first-episode/clean successes, internal retries, frontier replans, escalations, escaped defects discovered by separate development audit, user commands/interventions and total observed planning+probes+Run+checks+rework time/tokens/cost. Per metric report measured/eligible and scope/source; n/a is unknown. Partial/incomparable cost coverage forbids an aggregate total or ranking. The nine-family three-seed cohort is small: report n and paired per-case differences with uncertainty, not generalized superiority. A single seed is smoke. A real challenge arm requires a pristine initial state and fresh isolated agents; current local reports are retrospective evidence only. No original dataset or hidden labels ship.
